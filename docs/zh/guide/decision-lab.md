# 决策实验室

**决策实验室**向决策模型提出关于某个情境的类型化问题，并展示每个答案背后的概率。

**侧边栏位置：** 决策实验室（在缓存实验室下方）
**路由：** `/decision-lab`
**加入版本：** v0.7.0（2026 年 10 月）
**需要：** Ollama 0.35.1 或更新版本，以及一个决策模型（`nimble`、`tev1`、`clef-flash` 或 `clef`）

## 有什么用？

决策模型不生成文本。你给它一个**状态**（一张工单、一条消息、一行日志、一份文档）和一个或多个**问题**，它返回：

| 问题类型 | 返回内容 |
|---|---|
| **选择** | 选中的候选项、*每个*候选项的概率，以及置信度 |
| **是 / 否概率** | 条件成立的单一概率 |
| **刻度评分** | 在你的有序刻度上的期望位置、每一档的概率，以及置信度 |

这些概率是模型自身在候选项上的输出分布，而不是从一句话里解析出来的数字。这正是它们值得看的原因：问聊天模型"这紧急吗？"，它答*是*；问决策模型，它答 *0.99*，遇到模棱两可的工单则答 *0.55*，差别一目了然。

Ollama 通过 `/v1/systemone`（0.35.1 加入）提供这类模型。它们把 `decision` 作为**唯一**能力上报，所以 LLMxRay 把它们排除在所有对话和嵌入选择器之外，只在这里列出。给它们发送对话请求并不会干净地报错，而是回复自己 schema 的碎片，这正是需要过滤的原因。

## 使用页面

1. 选择一个决策模型。如果没有安装，在模型页拉取一个；`tev1:0.8b` 最小。
2. 描述**状态**。所有问题都针对这一段文字。
3. 编辑**问题**。每个问题有答案键（结果以此为键返回）、类型、指令，选择和评分类型还需要候选项列表：
   - **选择**：每行一个，格式为 `名称: 描述`。
   - **评分**：每行一个，从低到高。顺序*就是*刻度。
   - Ollama 每次请求接受 2 到 26 个候选项、1 到 64 个问题；超出范围时页面会在发送前提示。
4. **判断**。答案以条形图显示在右侧，选中项高亮，并附输入、输出 token 数和往返时间。

页面打开时自带一个完整示例：一张客服工单，以三种方式提问，每种类型一个问题。这正是验证 Ollama 0.40.3 时实际运行过的请求。

## 解读答案

- **选择**：条形按概率排序。高亮的是模型的选择。置信度是模型自己报告的数字。
- **是 / 否**：显示为*是*和*否*两条，总和为 1。
- **评分**：条形保持刻度顺序，因为位置即含义。高亮的是概率最高的一档。*评分*数值是期望位置（按概率加权），因此可能落在两档之间：四档刻度上的 2.37 意味着"重大，偏向完全中断"。

## 此页面不做什么

它不流式输出（该端点从不流式），不保存历史，也暂不发送图片，尽管 `clef` 和 `clef-flash` 支持。它只是一个观察决策模型真实返回内容的观测台，仅此而已。
